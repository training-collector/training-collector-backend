# Training Collector Backend

HTTP API на Ktor. Платформа хранит данные в PostgreSQL 16 и применяет миграции Flyway при запуске.

## Запуск

Нужны JDK 25 и PostgreSQL. Скопируйте `.env.example` в `.env` и заполните `DB_NAME`, `DB_USER` и `DB_PASSWORD`. По умолчанию платформа подключается к `jdbc:postgresql://localhost:5433/training`. Для внешней БД задайте `DB_JDBC_URL`, `DB_USER` и `DB_PASSWORD`. Пул настраивается через `DB_MAX_POOL_SIZE`.

Для первого запуска укажите существующую пустую базу. Бэкенд один раз применит `V1__training_collector.sql` и запишет версию в `flyway_schema_history`. После первого развёртывания этот файл не меняется: каждое следующее изменение схемы оформляется новым файлом `V<N>__*.sql`. Группы мышц, упражнения и цели создаются через админку. Боты записывают свои Telegram-имена при подключении.

Лимиты запросов, сроки жизни запросов входа, сессий и ссылок, интервалы очистки и остальные пороги перечислены с значениями по умолчанию в `src/main/resources/application.conf`. Под каждым значением указана переменная окружения, которая его переопределяет. Нулевое или отрицательное значение останавливает запуск. Лимиты отключаются только флагом `LIMITS_ENABLED=false`.

Для ботов сгенерируйте два независимых ключа командой `openssl rand -hex 32`. Значение `AUTH_SERVICE_KEY` укажите также в конфигурации бота авторизации, `TRAINING_SERVICE_KEY` — в конфигурации бота тренировок. Если ключи пусты, соответствующие служебные маршруты закрыты.

```sh
./gradlew run
curl http://localhost:8080/health
```

Для Docker выполните `docker build -t training-collector-backend .` и `docker run --env-file .env -p 8080:8080 training-collector-backend`. Внутри контейнера в `DB_JDBC_URL` укажите хост PostgreSQL, доступный из его сети. HTTP слушает `SERVER_HOST` и `SERVER_PORT`. Telegram-токены задаются только в соответствующих ботах.

## Развёртывание

Сервис разворачивается целиком на одном сервере, вместе с ботами, сайтами и PostgreSQL. Конфигурация и инструкция находятся в `training-collector-deploy`. Бэкенд там доступен только через nginx на `/api/v1/*` и `/admin/v1/*`, служебные маршруты `/internal/v1/*` видят только боты внутри сети Docker.

| Переменная | Значение |
|---|---|
| `DB_JDBC_URL`, `DB_USER`, `DB_PASSWORD` | Подключение к PostgreSQL. Пользователю нужны права на создание и обновление схемы для Flyway. |
| `AUTH_SERVICE_KEY`, `TRAINING_SERVICE_KEY` | Два разных секрета. Каждый бот получает свой ключ. |
| `APP_SECRET` | Секрет для подписи токенов, например `openssl rand -hex 32`. Если переменная пуста, секрет выводится из пароля БД, ключей ботов и пароля администратора, и их смена завершит все сессии. |
| `CLIENT_IP_HEADER` | Заголовок с адресом клиента от вашего прокси, например `X-Real-IP`. Без него лимиты по адресу считают все запросы через прокси одним клиентом. Указывайте только заголовок, который прокси выставляет сам. |
| `DB_MIGRATE_ON_START` | `false` запускает сервис без подключения к базе; миграции тогда выполняет отдельная команда `bin/training-collector-backend migrate`. По умолчанию миграции применяются при старте. |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Учётные данные администратора. |

Учитывайте лимит подключений PostgreSQL при настройке `DB_MAX_POOL_SIZE` (по умолчанию 5). Для активной разработки с IDEA используйте отдельные токены Telegram и локальную БД.

## Администрирование

Задайте `ADMIN_LOGIN` и `ADMIN_PASSWORD` в окружении бэкенда. Пустое значение закрывает вход. `POST /admin/v1/login` принимает `login` и `password`, возвращает токен на 8 часов. Для последующих запросов используйте Bearer. `POST /admin/v1/logout` отзывает токен.

- `GET /admin/v1/trainers` показывает привязавших Telegram тренеров. `POST /admin/v1/trainers/{id}/approve` одобряет заявку, бот авторизации сообщает об этом тренеру. Повторное одобрение активного тренера безопасно.
- `POST /admin/v1/trainers/{id}/deactivate` закрывает кабинет и обоих ботов, отзывает сессии, API-ключ, ссылки и запросы входа. `DELETE /admin/v1/trainers/{id}` удаляет также подопечных и их историю.
- `POST /admin/v1/trainers/{id}/activate` возвращает доступ к входу. Тренер может снова подключить бота тренировок из кабинета. При одобрении, деактивации и повторной активации auth-бот отправляет уведомление в привязанный Telegram.
- `GET /admin/v1/muscle-groups` возвращает группы мышц. Для создания используйте `POST /admin/v1/muscle-groups`, для изменения — `PUT /admin/v1/muscle-groups/{id}`, для удаления пустой группы — `DELETE /admin/v1/muscle-groups/{id}`. Передайте название в `name` и необязательное описание в `description`. Названия уникальны без учёта регистра. При создании или изменении упражнения укажите его `muscleGroupId`.
- `/admin/v1/exercises` и `/admin/v1/goals` поддерживают GET, POST и по идентификатору PUT и DELETE. Поле `hidden` управляет публикацией.

Вход администратора ограничен по адресу клиента: по умолчанию 5 попыток за 15 минут. Входы, одобрения, деактивации, удаления и правки справочников записываются в таблицу `audit_event` вместе с входами тренеров и удалениями записей. События хранятся 90 дней (`AUDIT_RETENTION`).

## Тесты

`./gradlew build` запускает проверки сервисов, миграций и HTTP API с Testcontainers. Нужен Docker. Сквозные проверки обоих Telegram-диалогов поднимают временную базу и настоящий HTTP-сервер. Они запускаются отдельно при наличии исходников обоих ботов в любых каталогах:

```sh
./gradlew -p integration test -PtrainingBotDir=/path/to/training-collector-bot -PauthBotDir=/path/to/training-collector-auth-bot
```

## Записать первую тренировку

Пример для `bash` и `jq`. После входа передайте токен веб-сессии из ответа `POST /api/v1/auth/login/status` в переменной окружения `TRAINER_TOKEN`.

```sh
api=http://localhost:8080/api/v1
auth="Authorization: Bearer ${TRAINER_TOKEN:?Укажите токен сессии}"

client=$(curl -fsS "$api/clients" -H "$auth" -H 'Content-Type: application/json' \
  -d '{"firstName":"Ирина","lastName":"Петрова"}' | jq -er .id)
# Сначала опубликуйте оба упражнения в админке.
exercises=$(curl -fsS "$api/catalog/exercises" -H "$auth")
crunch=$(jq -er '.[] | select(.name == "Скручивания") | .id' <<< "$exercises")
plank=$(jq -er '.[] | select(.name == "Планка") | .id' <<< "$exercises")

curl -fsS "$api/clients/$client/workouts" -H "$auth" -H 'Content-Type: application/json' -d "{
  \"performedAt\":\"2026-11-21T10:00:00+04:00\",
  \"durationMin\":45,
  \"exercises\":[
    {\"exerciseCatalogId\":$crunch,\"sets\":[{\"reps\":12,\"weightKg\":5},{\"reps\":10}]},
    {\"exerciseCatalogId\":$plank,\"sets\":[{\"durationSec\":45}]}
  ]
}"
```

Тренер определяется по токену, подопечный — по адресу запроса. Каждый подход содержит ровно один положительный целочисленный результат — `reps` или `durationSec`. Можно добавить `weightKg` в килограммах, `restSec` в секундах и `rpe` от 0 до 10. Каждое упражнение содержит хотя бы один подход. Тренировка сохраняется целиком в одной транзакции. В ответе `session` содержит дату и идентификаторы тренера, подопечного и тренировки, а `exercises` — упорядоченные пары `exercise` и `sets`.

## Замеры и история

Обхваты рук, предплечий, бёдер и голеней вводятся отдельно справа и слева. Ширину спины измеряют горизонтально по лопаткам между задними краями подмышек. Замеры прежнего формата сохраняются с пометкой «без указания стороны». Каждый POST добавляет запись на указанную дату. Отправляйте только измеренные показатели.

```sh
curl -fsS "$api/clients/$client/measurements" -H "$auth" -H 'Content-Type: application/json' \
  -d '{"measuredOn":"2026-11-01","heightCm":175,"weightKg":72.5,"waistCm":81}'
curl -fsS "$api/clients/$client/measurements" -H "$auth" -H 'Content-Type: application/json' \
  -d '{"measuredOn":"2026-11-21","weightKg":71.8,"calfCm":36}'
curl -fsS "$api/clients/$client/measurements" -H "$auth"
curl -fsS "$api/clients/$client/measurements/current" -H "$auth"
```

История возвращает обе записи с исходными датами, от новых к старым. В `current` у каждого показателя свои `value` и `measuredOn`. В примере актуальный вес равен 71,8 кг на 21 ноября, а последнее измерение талии — 81 см на 1 ноября. При нескольких записях одного показателя за день приоритет у последней добавленной.

| Поле | Показатель |
|---|---|
| `heightCm`, `weightKg`, `bodyFatPct` | Рост, масса тела, процент жира |
| `bicepsCm`, `waistCm`, `chestCm` | Обхваты руки, талии и груди |
| `hipsCm`, `thighCm`, `calfCm` | Обхваты по ягодицам, одного бедра и икры |
| `rightBicepsCm`, `leftBicepsCm` | Обхват правой и левой руки |
| `rightForearmCm`, `leftForearmCm` | Обхват правого и левого предплечья |
| `rightThighCm`, `leftThighCm`, `rightCalfCm`, `leftCalfCm` | Обхват каждого бедра и голени |
| `backWidthCm` | Ширина спины, см |
| `note` | Комментарий к записи |

## HTTP API

Префикс маршрутов — `/api/v1`. Для защищённых маршрутов передайте `Authorization: Bearer <token>`. При регистрации выдаётся ограниченный токен для привязки Telegram на 24 часа. Доступ к данным кабинета открывает веб-сессия, которую браузер получает после подтверждения входа в Telegram. Пока привязка не завершена, заявку можно отменить с сайта.

| Метод и путь | Назначение |
|---|---|
| `POST /trainers` | Создать заявку по `username`, `firstName`, `lastName`. Ответ содержит `trainer` и ограниченный `token` |
| `POST /trainers/me/telegram-link` | Получить `url` для Auth Bot и `expiresAt`. Ссылка действует до пяти минут. После `/start` заявка поступает администратору. После одобрения тренер входит обычным запросом входа. Привязавшему Telegram тренеру ссылка больше не выдаётся: ответ 403 |
| `GET /trainers/me` | Профиль с `telegramLinkedAt`, `approvedAt`, `trainingBotLinkedAt` и `timeZone` |
| `PUT /trainers/me` | Изменить собственные `firstName` и `lastName`. Возвращает обновлённый профиль |
| `PUT /trainers/me/time-zone` | Сохранить часовой пояс тренера в `timeZone`, например `Asia/Novosibirsk`. Кабинет передаёт пояс браузера сам. Бот считает в нём «сегодня» и показывает даты тренировок |
| `POST /trainers/me/training-bot-link` | После входа получить персональную ссылку на бота для тренировок на 10 минут. Подтверждается командой `/start` с того же Telegram-аккаунта |
| `POST /auth/login` | Запросить вход по `username`. Бот авторизации присылает тренеру сообщение с кнопками «Разрешить вход» и «Отклонить вход». Ответ содержит `secret` запроса, число `number` для сверки с сообщением, `botUrl` и `expiresAt`: запрос действует 5 минут. Ответ одинаков для существующего и несуществующего логина. Каждый запрос независим: новый не отменяет прежние |
| `POST /auth/login/status` | Узнать по `secret`, ответил ли тренер: `status` равен `PENDING`, `APPROVED`, `DENIED` или `EXPIRED`. При `APPROVED` ответ один раз содержит `token` веб-сессии и `trainer`. Сайт спрашивает раз в 2 секунды |
| `POST /auth/logout` | Завершить текущую сессию или отменить ещё не привязанную заявку |
| `POST /trainers/me/api-key` | Выпустить ключ для прямой интеграции с API по действующей веб-сессии. Ответ содержит `token` и `expiresAt`: ключ действует 90 дней |
| `POST /trainers/me/token` | Заменить текущий ключ API. Передайте этот ключ как Bearer. Сервер создаёт новый ключ сам и возвращает `token` и `expiresAt`, старый ключ сразу отозван |
| `POST /clients`, `GET /clients` | Создать и получить список своих подопечных. Для списка с архивом — `?includeArchived=true`. При создании можно передать `sex`, `age`, `telegramUsername` и первый замер в `measurement` |
| `GET /clients/{id}`, `PUT /clients/{id}` | Прочитать или заменить поля карточки — `firstName`, `lastName`, `goal`, `notes`. Поля `sex`, `age` и `telegramUsername` сохраняют прежние значения, если не переданы |
| `GET /trainers/me/bot-links` | Адреса чатов бота авторизации и подключённого тренировочного бота для профиля тренера |
| `GET /catalog/muscle-groups` | Группы мышц, созданные администратором |
| `GET /catalog/exercises`, `GET /catalog/muscle-groups/{id}/exercises` | Опубликованные общие упражнения целиком или по выбранной группе мышц |
| `POST /clients/{id}/workouts`, `GET /clients/{id}/workouts` | Записать тренировку или получить историю. Фильтры — `from` включительно, `to` исключительно (ISO 8601 с часовым поясом), `exercise` по части названия |
| `GET /workouts/{id}` | Получить тренировку с упражнениями и результатами подходов |
| `PUT /sets/{id}` | Заменить результат подхода. Тело того же формата, что при создании. Успешный ответ — 204 |
| `POST /clients/{id}/measurements`, `GET /clients/{id}/measurements` | Добавить датированный замер или прочитать историю |
| `GET /clients/{id}/measurements/current` | Прочитать последнее значение и дату измерения каждого показателя |
| `POST /client-errors` | Записать в журнал сервера ошибку страницы: `message`, необязательные `source` и `stack`. Доступен без токена, ограничен по адресу клиента |

Операции редактирования и удаления доступны владельцу записи:

| Метод и путь | Действие |
|---|---|
| `POST /clients/{id}/archive`, `POST /clients/{id}/restore`, `DELETE /clients/{id}` | Архивировать, вернуть или удалить карточку вместе с историей |
| `PUT /workouts/{id}`, `DELETE /workouts/{id}` | Изменить дату, длительность и заметку или удалить тренировку |
| `POST /workouts/{id}/exercises`, `DELETE /exercises/{id}` | Добавить упражнение с подходами или удалить его |
| `POST /exercises/{id}/sets`, `DELETE /sets/{id}` | Добавить или удалить подход |
| `PUT /measurements/{id}`, `DELETE /measurements/{id}` | Исправить датированную запись целиком или удалить её. Каждая правка увеличивает `version`. С параметром `?expectedVersion=N` правка записи, которую уже изменили, отклоняется с ответом 409 |

Для записи передайте `exerciseCatalogId` из общего справочника и `sets`. Старые клиенты могут передать имя опубликованного упражнения. Сервер возвращает 404 для неизвестного или скрытого упражнения. Доступные цели возвращает `GET /catalog/goals`. В карточке подопечного поле `goal` содержит название.

Тренировочный бот отменяет начатую запись запросом `DELETE /internal/v1/training/chats/{sender}/clients/{id}/workouts/active/{sessionId}` без тела. Нужны ключ тренировочного бота и привязанный чат тренера. Для своего подопечного тренер получает HTTP 200 с JSON-значением `true`, если указанная активная тренировка удалена вместе с подходами, или `false`, если такой активной записи уже нет.

Для завершения тренировки бот вызывает `POST /internal/v1/training/chats/{sender}/workouts/{id}/finish`. Необязательный параметр запроса `durationMin` задаёт длительность в минутах положительным целым числом. Повторное завершение возвращает сохранённую тренировку с её текущей длительностью.

При создании тренера, подопечного, тренировки, упражнения в тренировке, подхода или замера сервер возвращает 201. Для некорректного ввода API возвращает 400, для отсутствующего или недействительного токена — 401, для отсутствующей или чужой записи — 404. Ответ 403 означает, что действие недоступно для этого вида доступа: например, незавершённой регистрации или ключа API вместо сессии. При превышении лимита запросов сервер отвечает 429 с заголовком `Retry-After`, на тело запроса больше 1 МиБ — 413.

Регистрация, запрос входа, опрос его статуса и вход администратора ограничены по адресу клиента, авторизованные запросы — по тренеру. Значения лимитов заданы в `application.conf`. Токены сессий и ключи API содержат подпись сервера: запрос с чужим или случайным токеном отклоняется без обращения к базе. Даты тренировок и замеров принимаются с 1900 по 2100 год.
